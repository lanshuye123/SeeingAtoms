# 三级信息架构

> 用途：把“观众该看到的”和“操作员/制作者才需要知道的”分开，避免技术细节漏进成片。
> 适用：本系列所有视频、封面、简介、字幕、片尾、宣传物料。
> 相关文档：[反 AI 味工作法](writing_guide.md)、[技术路线](technical_route.md)。

## 1. 一句话

**观众只需要科学内容、可信的表达和必要的署名；操作员需要可复现的命令、路径、依赖和许可证；Agent 的内部推理、提示词、工具调用和调试过程，不进入交付物。**

## 2. 三层定义

| 层级 | 对象 | 可见内容 | 存放位置 |
|---|---|---|---|
| L0 最终观众 | 读者/观众 | 标题、旁白、字幕、动画、概念图、公式、坐标轴、必要片尾署名 | `chapters/s01/renders/` 的成片、SRT、封面 |
| L1 操作员/制作者 | 你、未来的制作者、审阅者 | 技术路线、运行命令、依赖、日志、素材来源、许可证、构建说明、已知问题 | `docs/`、`scripts/`、`chapters/s01/README.md`、`logs/` |
| L2 内部工作层 | Agent/模型/工作流 | 提示词、内部推理、工具调用、失败重试、临时草稿、调试坐标、未采纳方案 | 不交付；必要时只在 `logs/` 留最小可审计记录，且不进入 L1 的对外文档 |

## 3. 判定树

新增一条信息时，依次问：

1. **观众需要它才能理解科学内容或信任视频吗？**
   - 是 → L0。例如：布拉格公式、衍射角、晶面间距、字幕、必要的素材署名。
   - 否 → 下一步。
2. **操作员需要它才能复现、检查、维护或合法使用吗？**
   - 是 → L1。例如：命令、路径、依赖版本、字体许可证、素材 URL、已知问题。
   - 否 → 下一步。
3. **它只是“我们是怎么做出来的”或“Agent 怎么想的”吗？**
   - 是 → L2，不进入交付物。

## 4. L0 可以出现什么

- 科学概念、公式、单位、坐标轴、示意图、标注。
- 实验现象的简化图示；明确标注“示意/模型数据”的合成图。
- 旁白、字幕、标题、章节名。
- 必要的版权/素材署名，简洁到一行。
- 与科学内容直接相关的历史信息（如“1913 年，布拉格父子”）。

## 5. L0 不能出现什么

- 终端、命令行、代码编辑器、文件管理器、安装界面。
- 绝对路径、项目路径、环境名（conda/uv/venv）、软件版本号。
- 安装日志、错误堆栈、调试输出、API Key、模型名。
- Agent 提示词、内部推理、工作流步骤、工具水印。
- 与科学无关的“制作花絮”，除非它本身是科普内容。
- 未授权的论文插图、厂商宣传图、社交媒体图片。

### 例外

- 公式、坐标轴、标注、单位是教学内容，不是“技术细节”。
- 法律要求的版权署名可以出现在片尾；许可证全文放 L1。
- 教学确实需要展示软件界面时，先问操作员，并做遮挡/重绘，不展示路径和个人信息。

## 6. 文档落位

| 内容 | 层级 | 位置 |
|---|---|---|
| 系列定位、风格、受众 | L1 | `docs/program_mainline.md` |
| 反 AI 味方法 | L1 | `docs/writing_guide.md` |
| 三级信息架构 | L1 | 本文 |
| 工具链、环境、渲染流程 | L1 | `docs/technical_route.md` |
| 科学依据、课程笔记出处 | L1 | `docs/references.md` |
| 字体/素材/音乐许可证 | L1 | `docs/assets_and_licenses.md` |
| 片尾署名 | L0/L1 | `docs/credits.md`（草案）；成片只留简洁版 |
| 运行命令 | L1 | `scripts/README.md`、`Makefile` |
| 单期脚本/分镜/计划 | L1 | `chapters/s01/*.md` |
| 成片/字幕 | L0 | `chapters/s01/renders/` |
| 环境检查/渲染日志 | L1 | `logs/` |
| Agent 提示词/内部推理 | L2 | 不交付 |

## 7. 三个审核闸门

### 闸门 A：文案定稿前

- 旁白/字幕/画面文字里有没有路径、命令、环境名、软件名？
- 有没有把“制作过程”当内容讲？
- 公式和术语是否必要、是否解释？
- 片尾署名是否简洁、合规？

### 闸门 B：渲染前

- 分镜里的屏幕文字只保留 L0 内容。
- 场景文件不把日志/路径/版本号写进画面。
- 合成数据标注“模型数据，非实测”。

### 闸门 C：导出前

- 抽帧检查：终端、代码、文件管理器、工具水印、调试网格。
- 字幕检查：没有内部术语、文件名、命令。
- 片尾检查：只有必要署名；许可证全文在 L1。
- 元数据检查：标题/简介不泄露内部路径或工作流。

## 8. 常见错误

| 错误 | 为什么不行 | 改法 |
|---|---|---|
| 把“用 Manim 渲染”写进旁白 | 观众不关心工具，且破坏沉浸 | 删除；技术说明放 L1 |
| 画面角落放软件版本号 | 工具水印/版本信息与科学无关 | 删除；版本记录在 L1 |
| 用真实论文插图但不标来源 | 版权风险 | 改用自制示意图，或取得授权并署名 |
| 把“模型数据”说成实测 | 误导 | 画面标注“模型数据，非实测” |
| 片尾放许可证全文 | 观看体验差 | 片尾一行署名；全文放 `docs/assets_and_licenses.md` |
| 把 Agent 的失败重试写进“制作花絮” | 观众不关心，且可能泄露内部信息 | 只留 L1 日志，不进入成片 |

## 9. 复用方式

新开一期时：

1. 复制 `chapters/s01/` 的结构为 `chapters/s02/`；
2. 先读本文和 `docs/writing_guide.md`；
3. 文案/分镜完成后，按三个闸门自查；
4. 成片只从 `renders/` 取，不从 `logs/`、`media/` 直接取未审核素材。
